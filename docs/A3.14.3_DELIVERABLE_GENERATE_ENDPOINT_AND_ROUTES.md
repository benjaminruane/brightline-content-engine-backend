## Task D — vercel.json includeFiles and paths

**Current config (vercel.json):**
```json
"functions": {
  "api/*.js": {
    "maxDuration": 60,
    "includeFiles": "{_lib/web.js,lib/analyse-statements-impl.mjs,lib/analyse-statements-helpers.cjs}"
  }
}
```

**Paths relative to deployment (project) root:**

| includeFiles entry | Path from repo root | Exists? |
|-------------------|---------------------|--------|
| **lib/analyse-statements-impl.mjs** | `lib/analyse-statements-impl.mjs` | ✅ Yes |
| **lib/analyse-statements-helpers.cjs** | `lib/analyse-statements-helpers.cjs` | ✅ Yes |
| **_lib/web.js** | `_lib/web.js` | ❌ No (no `_lib/` at project root) |

**Actual locations:**
- `api/_lib/web.js` — exists (used by some api routes; generate uses `../lib/web.js` = `lib/web.js`).
- `lib/web.js` — exists; **api/generate.js** imports `../lib/web.js` (i.e. `lib/web.js`).

**Conclusion:**  
- `lib/analyse-statements-impl.mjs` and `lib/analyse-statements-helpers.cjs` are correct and exist.  
- `_lib/web.js` does **not** exist at project root; the only match in the repo is `api/_lib/web.js`. In Vercel, includeFiles are usually relative to the project root, so `_lib/web.js` can cause “file not found” or be ignored. If analyse-statements (or any api route) needs `api/_lib/web.js`, the intended value may be **api/_lib/web.js**.  
- **api/generate.js** does not use `_lib`; it imports **lib/web.js**, which is at `lib/web.js` and is not listed in includeFiles. Vercel still bundles dependencies by following imports, so generate can load `lib/web.js` without it being in includeFiles. The includeFiles are mainly for forcing in the large impl/helpers used by analyse-statements.

**Recommendation:** If you see import-time or “file not found” errors for `_lib/web.js`, change includeFiles to use **api/_lib/web.js** (if that file is required for any api route). If no route uses `api/_lib/web.js`, you can remove `_lib/web.js` from the list.
