# A5.44 — QC Pipeline Wide Trace (Read-Only)

End-to-end map of the QC (Review) pipeline: how statements, references, citations, excerpts, support levels, web rescue, and conflicts are created and surfaced. No behaviour changes; description of current state only.

---

## QC pipeline explained (like I'm Ben)

You click **Review**; the app sends draft text, version id, and sources to the backend. The backend runs one big handler in `lib/analyse-statements-impl.mjs`: it prepares uploaded sources (including PDF/DOCX extraction), builds a **unified reference list** (uploaded first with ids 1..N, then web with N+1..M), does optional **Tavily web search** for context, then calls **OpenAI** to get raw statements with claims and citation ids. Those statements go through **citation resolution** (drop refs that don't exist), **verification gating** (force Low if no citations, inject memo citation for document-descriptive when appropriate), **normalize response** (mirror citations + build **evidence** from refs — title/url/sourceType only, **no excerpt** in evidence array). Later, **evidence bundles** are built per statement from **corpus search hits** (which have excerpts) and/or **web ref snippets**; that’s where **primary.excerpt** comes from. **Conflicts** are detected from canonical claims and corpus values (same type, different values, multiple sources) and from reason-text patterns ("conflicts with"); support level (High/Medium/Low) is set by verification gates and score. **Rescue** (web search for unsupported statements) runs after the main pipeline when Tavily is enabled and can add web refs and upgrade statements. The **final response** is built once after rescue; then **extractionQuality**, **supportTopology**, **contradictionSignals**, **suggest**, and doc-level **judgement** are filled in. So: **citations** are ref ids on the statement; **evidence** is a list of { title, url, sourceType } from those refs; **excerpt** lives only in **evidenceBundle.primary** when corpus or web gave a snippet. That’s why you can get a **citation without excerpt**: ref is cited and in evidence, but no corpus hit and no web snippet (or buildEvidenceBundle failed), so primary is null and the guard strips "Confirmed" from reasons.

## 1. Pipeline map (numbered, execution order)

### Entry and request

1. **`api/analyse-statements.js`** or **`api/analyse-statements-v2.js`**  
   - **In:** `req`, `res`. V2 sets `req.body.engine = "v2"`.  
   - **Out:** Calls entry; sends `res.status(200).json(payload)`. V2 only sets `ok: true` when `meta.fullPipelineCompleted === true`.  
   - **Invariants:** POST, CORS handled.  
   - **Failure:** Throws if entry/impl throws.

2. **`api/analyse-statements-entry.js`**  
   - **In:** `req` (with `_brightlineRid` or header), `res`.  
   - **Out:** Dynamic import of `lib/analyse-statements-impl.mjs`, returns `impl(req, res)`.  
   - **Invariants:** Impl default export is a function.  
   - **Failure:** Throws on import/export failure.

### Handler init and body

3. **`lib/analyse-statements-impl.mjs`** (handler)  
   - **In:** `req.body` (draftText, versionId, sources, web, publicSearch, selectionText, etc.).  
   - **Out:** Eventually `finalResponseObject` or fallback payload.  
   - **Invariants:** OPENAI_API_KEY set; POST; body parseable.  
   - **Early returns (ok:true):** OPTIONS → `{ ok: true, statements: [], references: [], meta: { options: true } }` (line ~25975).  
   - **Early returns (ok:false):** Wrong method, missing OPENAI_API_KEY, source ingestion error, helpers init failure (selection), budget exhausted, OpenAI timeout; all return statements/references/meta with fatal/fatalStage.

### Source ingestion and references

4. **`prepareUploadedSourcesForPipeline`** (from `lib/extract-text-from-source.mjs`)  
   - **In:** `sources` array.  
   - **Out:** `{ sources, warnings, sourceIngestionWarning, totalTextLowWarning, thresholds }` or `{ error }`.  
   - **Invariants:** Max size, timeout.  
   - **Failure:** On error, handler returns ok:false, fatalStage `source_ingestion`.

5. **Uploaded references build** (inside impl, ~26563–26570)  
   - **In:** Prepared `sources`.  
   - **Out:** `uploadedReferences`: `{ id: idx+1, title, url, type: "uploaded", sourceType: "uploaded" }`. No excerpt/snippet on uploaded refs.

   - **In:** `uploadedReferences`, `webReferencesWithIds`.  
   - **Out:** `unifiedReferences = [...uploadedReferences, ...webReferencesWithIds]`.

### Extraction and OpenAI

8. **Statement extraction** (v1: in-impl; v2: `extract-statements.mjs`)  
   - **In:** Normalized draft (or selection text), mode.  
   - **Out:** `rawExtractionCandidates` (statement strings), selection metadata.  
   - **Invariants:** Selection mode uses only selected text.  
   - **Failure:** Fallbacks exist for empty extraction (e.g. single selection string).

## 2. Data dictionary (as in code)

### Statement object (final response)

- **id:** Optional; set on success path as `stmt_${versionId}_${index}` (impl ~33627).  
- **text:** Statement text.  
- **citations:** Array of reference ids (numbers or strings); mirrored from assessment.citations by normalizeResponseStructure.  
- **evidence:** Array of { title, url?, sourceType }. No excerpt/snippet in this array (see normalizeResponseStructure).  
- **assessment:**  
  - **citations:** Same ids as top-level citations.  
  - **reasons:** Array of strings (capped at 3).  
  - **reliabilityScore,** **reliabilityLabel:** Number and "High"|"Medium"|"Low".  
  - **canonicalClaims:** Array of { type, value, unit, currency, citations, ... }.  
  - **rawClaims,** **evidence:** Optional; evidence here mirrors top-level when set.  
- **meta:** supportTopology, contradictionSignals (level, conflictTypes, conflictingTupleKeys), evidenceJudgement, evidenceStrength, suggest (items, summary), v2Reasoning, conflictNarrative, etc.  
- **evidenceBundle:**  
  - **primary:** { refId, sourceType, title, url, pageHint, **excerpt**, excerptType, excerptConfidence, quoteFingerprint } or null.  
  - **additional:** Array of same shape.  
  - **matchType:** "exact"|"rounded_equivalent"|"unit_equivalent"|"paraphrase"|"partial_support"|"none".  
  - **reasoning:** { headline, paragraph, deterministicVariantKey }.  
- **Support / typing:** reliabilityLabel and reasons reflect verification gates; role/type on claims from inferCanonicalType / roleKeywords (claim-level), not enforced against source "role" when binding.

### Reference object

- **id:** Numeric; 1..N uploaded, N+1..M web.  
- **title:** string.  
- **url:** string or null.  
- **type:** "uploaded" | "web".  
- **sourceType:** "uploaded" | "web_search" (canonical after normalizeReferenceSourceType).  
- **snippet:** Optional; only on web refs (from Tavily/content).  
- **credibilityTier:** Optional; web refs.  
- Uploaded refs do not have excerpt/snippet in the ref object; excerpt appears only in corpus hit → evidenceBundle.

### Citation concept (UI)

- **Backend:** Citation = reference id (number) in statement.citations / statement.assessment.citations.  
- **UI:** Citation number shown in chips = 1-based index in the list used for badges (backendEvidenceIds → evidenceForBadges). That list comes from meta.supportingReferences.supportingReferenceIds or meta.matcherSupport.agreementStrength.supportingSourceIds or assessment.citations, so **citation number in UI is not necessarily the reference id**; it’s the position in the evidence list for that statement.

### Excerpt / snippet

- **In reference:** Only web refs have `snippet` (from Tavily/content).  
- **In evidence array:** Not present; evidence entries are { title, url, sourceType } only.  
- **In evidenceBundle:** primary/additional have **excerpt** when (1) corpus search returned a hit with excerpt, or (2) citation is web ref with ref.snippet.  
- **Where stored:** evidenceBundle on statement; ref.snippet on web refs; corpus hits in-memory only (not stored on ref).

### Conflict representation

- **Per-statement:**  
  - **meta.contradictionSignals:** { level: "none"|"soft"|"hard", conflictTypes, conflictingTupleKeys, source: "corpus" }.  
  - **meta.conflictNarrative:** { hasConflict, ... }.  
  - **meta.conflictValues:** optional { items } for conflict value pairs (when BRIGHTLINE_DEBUG_CONFLICTS=1).  
  - **_conflictOverrideLow:** internal; drives reason text "The uploaded sources conflict on ..." and evidencePosture "conflicting".  
- **Doc-level:** meta.corpusContradictions: { tupleCount, conflictingTupleCount, items } (tupleKey, type, level, distinctValueCount, values, distinctSourceCount).  
- **Conflict detection sources:** (1) Canonical claims same type different values; (2) raw claims + corpus values; (3) identity probe on uploaded source text (same type, materially different value).  
- **Gating:** level "hard" when distinct values ≥ 2 and distinct sources ≥ 2 for same tuple (type|currency|unit).

### Web observability / web references

- **meta.web:** { enabled, used, provider: "tavily", mode, references: [{ id, title, url, snippet, credibilityTier, sourceType }], usedReferenceIds }.  
- **meta.webSearch:** pass1 (ran, reasonSkip, queriesCount, resultsRawCount, resultsKeptCount, resultsDroppedCount, error, used), rescue (ran, reasonSkip, candidatesCount, queriesCount, resultsRawCount, resultsKeptCount, resultsDroppedCount, upgradedStatementsCount, error, used), used.  
- **Web refs in references array:** Same shape as other refs; id > uploaded count; type "web", sourceType "web_search", snippet when available.

### Support reasoning / reasoning paragraph

- **evidenceBundle.reasoning.paragraph:** Built in buildEvidenceBundle when primary has excerpt; includes "Confirmed using provided sources:" or "Partially confirmed...", source name, [refId], and excerpt preview.  
- **assessment.reasons:** Bullet strings; "Confirmed" only allowed by a3918GuardAssessmentCiteReasons when evidenceBundle.primary.excerpt is present.  
- **meta.v2Reasoning:** agreementStrength, conflictSignals, evidenceCoverage, sourceSpread (supportingSourceIds, etc.).

## 3. "Where can this happen?" (explicit callouts)

### A) Citation without excerpt

- **normalizeResponseStructure** (impl ~9985–10005): Builds **evidence** from refs by citation id; pushes only `{ title, url, sourceType }`. No excerpt or snippet. So every statement that has citations gets evidence entries **without excerpt**. Excerpt is never in the evidence array.  
- **enforceCorpusVerificationBeforeAbsence** / **enforceAnchorCitationsAndAmbiguity** / **backfillCitations**: When they add citations and evidence from refs, they use the same pattern (title, url, sourceType only). No excerpt in evidence.  
- **applyDualAxisVerification**: Injects memo citation and builds evidence from ref (title, url, sourceType). No excerpt.  
- **buildEvidenceBundle** (impl ~20181):  
  - **Primary with excerpt** only when (1) corpusResult has hits with hit.excerpt, or (2) citation is web ref and ref.snippet exists. If statement has only uploaded refs and corpus search found no hit (or hit without excerpt), primary is null or primary.excerpt missing.  
  - **Web refs without snippet:** If web ref has no snippet (e.g. filtered, or not set), that citation does not contribute an excerpt in evidenceBundle.  
  - **buildEvidenceBundle throws:** Catch sets evidenceBundle to { primary: null, additional: [], ... }; statement keeps citations and evidence but no excerpt.  
- **a3918GuardAssessmentCiteReasons:** Allows "Confirmed" only when `hasCapturedExcerpt` (evidenceBundle.primary.excerpt). So after guard: if there’s citation + evidence but no primary excerpt, reasons show "Not confirmed in the provided source(s)." — i.e. **citation without excerpt** is the normal case whenever corpus has no hit or web has no snippet or evidenceBundle failed.

**Summary codepaths that produce citation without excerpt:**  
1) normalizeResponseStructure (all statements with citations).  
2) Any citation injection path that only copies ref title/url/sourceType (dual-axis, corpus enforce, anchor enforce, backfill).  
3) buildEvidenceBundle returning primary null or primary without excerpt (no corpus hit, or no web snippet, or throw).  
4) Web refs added without snippet (e.g. rescue refs if snippet not set).

### B) Role mismatch binding (source/excerpt attached despite mismatch)

- **resolveCitations:** Only checks that citation id exists in unifiedReferences. No check that ref type or "role" matches claim type (e.g. valuation vs investment). So a ref can be bound to any statement that cites it.  
- **normalizeResponseStructure:** For each citation id, looks up ref and pushes { title, url, sourceType }. No role or claim-type check.  
- **buildEvidenceBundle:** Builds candidates from (1) corpus hits (docId → refId via docIdToRefId; no claim-type check on ref), (2) web citations with snippet. Selection of primary is by sourceType (uploaded > web), then matchType, then excerpt length. **No check that the ref or excerpt is for the same “role” or claim type** (e.g. ownership vs valuation). So a corpus hit from a doc that discusses both ownership and valuation can attach to a statement whose canonical claim is valuation.  
- **enforceCorpusVerificationBeforeAbsence / enforceAnchorCitationsAndAmbiguity / backfillCitations:** Inject citations by finding support in corpus or memo; they do not validate that the supporting text’s “role” matches the claim’s type.  
- **Conflict detection:** Uses tuple key (type|currency|unit) and distinct values/sources; it does not prevent a source from being attached to a claim of different type — it only flags conflict when same type has different values across sources.  
- **Conclusion:** There is **no step that prevents a source/excerpt from attaching to a statement (or claim) when the source’s “role” or document context doesn’t match the claim type**. Binding is by ref id and corpus hit presence / web snippet presence, not by role/type match.

### C) Conflict appears or disappears between runs

- **Non-determinism:**  
  - **OpenAI temperature:** Default 0; can be overridden by REVIEW_MODEL_TEMPERATURE. Non-zero adds variance in extracted claims/citations/reasons.  
  - **Ordering:** conflictLevelByTupleKey and conflictingItems use sorted iteration (corpusTupleKeysSorted); statement-level conflictTypes/conflictingTupleKeys use sorted arrays — so ordering is stable for same inputs.  
  - **Rescue:** Re-assessment and which statements get upgraded can vary if Tavily results or filtering change.  
  - **Corpus search:** If extraction or doc text changes slightly, hits (and excerpt) can change; then evidenceBundle and support signals can change.  
- **Gating differences:**  
  - **distinctValueCount / distinctSourceCount:** Conflict level is "hard" when distinctValueCount > 1 and distinctSourceCount >= 2 for same tuple. If one run has one value per source and another run merges or splits refs, counts can differ.  
  - **Canonical claims vs raw claims:** Conflict can be set from canonical claims, raw claims, or identity probe. If extraction or canonicalization differs (e.g. different claims extracted, or different typing), conflict flags can differ.  
  - **Evidence clearing:** When emitted support is cleared (low reliability, no evidence), citations/evidence are zeroed and conflict narrative may not be built for that statement.  
- **Fallbacks:**  
  - **buildEvidenceBundle** on error sets primary null; that can change reason text (e.g. "Not confirmed") and downstream meta.  
  - **finalResponseObject** fallback (after FINAL_COUNTS) in catch can return a payload that was built before full conflict/consistency passes if a later step threw.  
- **Selection vs full draft:** In selection mode, statement set and corpus context differ; conflict detection runs on the returned statement set and corpus state, so results can differ from full-draft run.  
- **Plausible causes from code:** (1) Temperature > 0 or model variance; (2) different corpus hits (extraction/source text); (3) rescue adding/removing web refs or upgrading statements; (4) different canonical/raw claim set (typing or extraction); (5) finalResponseObject returned from catch before full conflict/consistency; (6) evidence clearing changing which statements have support and thus conflict narrative.

## 4. UI consumption map

### Payload fields used by QC UI

- **Statement cards (rows):**  
  - **statementRows** = `currentAnalysis.statements` = `data.statements` from API.  
  - **result** = `currentAnalysis.result` = full `data` (statements, references, meta).  
  - **rows** = derived from statementRows + result (with id, text, score, level, assessment, citations, evidence, meta, backendEvidenceIds, evidenceForBadges, etc.).  
  - **row.id,** **row.text,** **row.assessment.reasons,** **row.assessment.reliabilityScore/Label,** **row.citations,** **row.evidence,** **row.meta** (supportTopology, contradictionSignals, evidenceStrength, suggest, conflictNarrative, conflictValues), **row.evidenceBundle**, **row.backendEvidenceCount**, **row.sourceCount**.

- **Citations in statement cards:**  
  - **row.citations** / **row.assessment.citations** for presence and count.  
  - **row.evidenceForBadges** (fallback **row.evidence**) for badge list; each entry { title, url, sourceType } for CitationPopover.  
  - **backendEvidenceIds** from **getCanonicalBackendEvidenceIds(raw)** (meta.supportingReferences.supportingReferenceIds, meta.matcherSupport.agreementStrength.supportingSourceIds, meta.matcherSupport.sourceSpread.supportingSourceIds, meta.supportingSourceIds, raw.supportingSourceIds).  
  - **evidenceForBadges** = backendEvidenceIds.map(refId => referencesById.get(refId)) → { title, url, sourceType }. So **citation chips use backend meta order**, not necessarily the order of row.citations.  
  - **InlineSourceChips** render citation number as **1-based index** (i+1) in the evidence list (chipData), not the reference id.

- **Popovers:**  
  - **CitationPopover:** source = { title, url, body, sourceType } from evidenceForBadges/evidence. **body** is not set in backend evidence entries; popover shows title/url/sourceType.  
  - **MoreExcerptsPopover:** uses **row.evidenceBundle.additional** (excerpts).

- **QC summary:**  
  - **result.meta** (judgement, scoringBridge, suggestSummary, extractionQuality, fullPipelineCompleted).  
  - **result.references** length.  
  - Counts from statementRows/rows (high/medium/low, verdict counts).

- **Themes panel:**  
  - **rows** / **statementRows** grouped by theme (evidence_support, overreach_unsupported, conflicts_consistency, deal_structure, narrative_editorial, suggestions_queue).  
  - Uses same row fields (verdict, meta.contradictionSignals, meta.suggest, etc.).

### Reindexing / drift risk

- **referencesById:** Built in frontend from **result.references** (Map by ref id). Used to build evidenceForBadges from backendEvidenceIds. If backend sends references in different order or with different ids between runs, ref lookup is still by id — no reindexing of references array itself.  
- **Citation numbers (1, 2, 3...):** Come from **order of backendEvidenceIds**, which comes from meta (supportingReferenceIds, matcherSupport.supportingSourceIds, etc.). That order can differ from **assessment.citations** order. So **citation number shown (1-based index) can differ from the position in statement.citations** — i.e. reindexing by backend meta.  
- **evidenceForBadges:** Built as backendEvidenceIds.map(refId => ref). If backendEvidenceIds is empty (e.g. emitted support cleared), evidenceForBadges is []; UI then falls back to row.evidence. So **two sources of evidence list** (backend meta vs assessment.citations/evidence); if they diverge, badge order and count can differ from raw citations.

## 5. Gating conditions (concise)

- **Attach references/excerpts to statements:**  
  - Refs attached by **citation id** in assessment.citations (after resolveCitations).  
  - **Evidence** (title, url, sourceType) attached in normalizeResponseStructure and in citation-injection paths (dual-axis, corpus enforce, anchor enforce, backfill); **no excerpt** in evidence.  
  - **Excerpt** attached only in **evidenceBundle.primary** when buildEvidenceBundle gets (1) corpus hit with excerpt, or (2) web citation with ref.snippet.

- **Mark statements supported/confirmed:**  
  - **Supported:** Has resolved citations and passes dual-axis (CITED_OK or MEMO_OK); score from reliabilityScore/Label (High/Medium/Low) and verification gates (force Low when no citations, etc.).  
  - **Confirmed (reason text):** a3918GuardAssessmentCiteReasons allows "Confirmed" only when assessment.citations, assessment.evidence, and **evidenceBundle.primary.excerpt** are present.

- **Detect conflicts:**  
  - **Corpus-level:** Same tuple (type|currency|unit), distinct values, ≥2 distinct sources → level hard/soft; meta.corpusContradictions.  
  - **Per-statement:** contradictionSignals from corpus tuple keys; _conflictOverrideLow from canonical claims, raw claims + corpus, or identity probe (uploaded text same type different value).  
  - **Reason text:** Patterns like "conflicts with" in reasons; enforceReasonSpecificity can rewrite to explicit conflict sentence.

- **Run rescue / web search:**  
  - **Pass 1:** webMode === "ON" and Tavily enabled; query from draft/sources; results filtered, formatted, added to webReferencesWithIds.  
  - **Rescue:** After main pipeline; enableTavily and rescue candidates exist; Tavily per candidate; filter; optional re-assessment; append web refs; upgrade statements that get new citations.

- **Populate UI model:**  
  - **statements** and **references** from response; **result** = full payload.  
  - **rows** = statementRows mapped with referencesById, getCanonicalBackendEvidenceIds, evidenceForBadges.  
  - **Citation numbers** = 1-based index in evidenceForBadges (from backendEvidenceIds).
