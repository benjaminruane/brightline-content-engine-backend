## The four numbers

| # | Measure | Result |
|---|---|---|
| 1 | FALSE notes that now read "No change was made" | **1 of 9** |
| 2 | UNCLEAR notes now checkable | **13 of 13** |
| 3 | ACCURATE notes whose wording changed | **62 of 62**, of which **41 lost an embedded justification** |
| 4 | **Total notes that now say no change was made** | **1 of 84** |

Two of these need reading carefully, because the bare number misleads in
opposite directions.

**Number 1 understates the fix.** Only 1 of the 9 FALSE notes became "No change
was made", but **all 9 stopped making a false claim.** Eight of the nine are the
same defect repeated across runs: the model claimed it removed both the
"lead commitment" characterisation *and* the June 2025 timing. Neither was
removed. The only edit inside that span was the deletion of the words
"We were". The new note now says exactly that:

> **Old:** Removed the specific 'lead commitment' characterization and June 2025
> timing, which are not supported by the source, while retaining the
> relationship and fund description.
>
> **New:** Removed "We were" - which are not supported by the source, while
> retaining the relationship and fund description.

The invented two-part removal is gone. What remains is the one-word edit that
actually happened, plus the model's reason. That is the whole point of the
change, and it fires on 8 notes that the previous pass could only label FALSE
without being able to correct.

**Number 4 is a floor, not the coverage gap.** The spec expected this number to
be uncomfortable. It is 1, and the reason is structural rather than reassuring:
the 84 rows come from artefacts whose notes had *already been through marker
honesty*, which rewrites pure no-change notes to "Left this wording as written".
2dcc796 then selected only *removal-asserting* notes, so any note honesty had
already caught was filtered out of the 84 before this replay ever saw it. **The
real no-change rate cannot be measured from these artefacts.** It can only be
measured from raw model output on future runs, which this change now makes
visible for the first time.

## What changed

Every marker note is now assembled in two parts:

- **WHAT** — generated by code from the real difference between the original
  region and the revised span.
- **WHY** — taken from the model, unchanged and unvalidated.

The model's account of what it did is parsed out and discarded.

The diff uses `markerSpanAlignment` from `lib/pr9-marker-span-status.mjs` — the
same comparator marker honesty uses — so the note and the honesty verdict are
computed from one window and cannot disagree.

### Exact final strings, after `normalizeMarkerNoteText`

Confirmed by running them; the quotation survives normalization intact.

| Case | With a model reason | With no reason |
|---|---|---|
| removed only | `Removed "and highly regarded" - the source does not back it. Confirm before publishing.` | `Removed "and highly regarded". Confirm before publishing.` |
| added only | `Added "approximately" - the source does not back it. Confirm before publishing.` | `Added "approximately". Confirm before publishing.` |
| replaced | `Replaced "14 per cent" with "12%" - the source does not back it. Confirm before publishing.` | `Replaced "14 per cent" with "12%". Confirm before publishing.` |
| two edits | `Removed "bravo", Added "foxtrot" - the source does not back it. Confirm before publishing.` | `Removed "bravo", Added "foxtrot". Confirm before publishing.` |
| four edits | `Made 4 separate edits to this passage - the source does not back it. Confirm before publishing.` | `Made 4 separate edits to this passage. Confirm before publishing.` |
| **no change** | `No change was made - the source does not back it. Confirm before publishing.` | `No change was made. Confirm before publishing.` |

Quoting rules as specified: verbatim, markers stripped, whitespace collapsed,
embedded double quotes downgraded to single so the outer quotation stays
readable, truncated at 80 characters with an ellipsis, and more than three
separate edits stated as a count.

## Reason extraction, and one defect found and fixed mid-measure

The first replay reported **59 of 62** ACCURATE notes losing their reason. That
was a defect in my extraction, not a finding, and it is worth recording because
it nearly went into the report as one.

The note template asks for `<what> — <why>`, so extraction initially keyed on
that separator alone. The model frequently ignores it and introduces the reason
with a semicolon or a connective instead:

- `Removed the 'top quartile' ranking; the source does not provide a quartile comparison.`
- `Changed 'has returned' to 'is currently marked at' to match the source language.`

Extraction now takes whichever reason marker appears first: a separator (dash or
semicolon, dropped) or a connective (`because`, `since`, `to match`, `to reflect`,
`as the source`, …, kept, since "to match the source" reads wrong with the "to"
removed). That moved reason loss from 59 to **41**.

### The 41 that remain, and the honest cost of this change

The remaining 41 are notes with **no separable reason clause at all**. The
justification is fused into the what as an adjective:

> Removed the **unsupported** 'top quartile of European lower-mid-market
> managers' ranking and retained only the supported performance data.

becomes

> Replaced "exits, placing it in the top quartile of European lower-mid-market
> managers." with "exits.".

The edit description is now correct and specific where before it was vague. But
the word "unsupported" — the model's judgement of *why* — is gone, and nothing
replaces it. The spec is explicit that a note which is entirely an account of
what it did should emit the what clause alone rather than invent a reason, so
this is the specified behaviour, not a bug. **It is still a real loss on 41 of
84 notes and should be a conscious decision rather than a side effect.**

The cleanest future fix is a prompt change so the model always emits a
separated reason clause, which this spec forbids. Flagging it rather than
working around it.

## Interaction with existing machinery

### Deterministic removal notes: untouched

`applyNoteWhatFromDiff` runs **before** `applyDeterministicUnsupportedRemoval` in
`finalizeSuggestRevisionText`. Removal markers are created after this stage, so
they cannot pass through it by construction rather than by an exclusion rule
that could rot. Verified by test.

### Marker honesty: two note rewrites are now dead

Measured, not asserted. With generated notes:

| Contradiction | Status now |
|---|---|
| `changed_but_identical` → note rewrite | **Dead.** Fires on `spanStatus === UNCHANGED`, the exact condition under which the builder already emits "No change was made". Same comparator, same window. |
| `cut_but_region_unchanged` → note rewrite | **Dead**, for the same reason. |
| `note_intent_mismatch` | **Live**, and now does the work: flips intent to KEPT and keeps the generated note. |
| `cut_but_text_present` | **Live.** Uses `cutSpanTextPresentInRevised`, which is region-independent and not derivable from `spanStatus`, so it is *not* provably unreachable. Left alone. |
| `remnant_missed_edit` | **Live**, unchanged. |

**No honesty logic was deleted.** Standing the two rewrites down was done by
adding `no change was made` to the keep-language vocabulary in
`lib/pr9-marker-note-claim.mjs`, so honesty's existing `note_intent_mismatch`
branch recognises the generated clause, flips the intent and returns the note
intact — reaching the rewrite path becomes impossible. That is a one-line
change instead of surgery, and it leaves the rewrites in place to protect
hand-written and legacy notes. All intent handling is untouched.

Probe confirming the behaviour:

```
CHANGED intent, nothing changed → note_intent_mismatch, intent KEPT
  note: No change was made - the source never says this. Confirm before publishing.
CUT intent, nothing changed     → note_intent_mismatch, intent KEPT
  note: No change was made - unsupported. Confirm before publishing.
CHANGED intent, real edit       → no contradiction
  note: Removed "and highly regarded" - no source backs it. Confirm before publishing.
```

## What a user notices

Every note now describes an edit that actually happened. A flagged concern that
Suggest skipped says "No change was made" and still carries the reason, so it
reads as an open item rather than a solved one. Notes are more specific about
what moved and, on 41 of 84, less articulate about why.
